# Архивация и удаление учителей: что сделать на фронте

Документ описывает, как фронт должен работать с увольнением (архивацией), восстановлением и удалением учителей, и какие ответы возвращает бэкенд.

## Главное

У учителя два разных действия, и в интерфейсе их нельзя смешивать:

| Действие | Когда использовать | Что происходит | Обратимо? |
|---|---|---|---|
| **В архив** | Учитель уволился | Карточка уходит в архив, история занятий и выплат сохраняется | Да, кнопкой «Восстановить» |
| **Удалить** | Карточку создали по ошибке или это дубль | Запись удаляется из базы. Работает **только если у учителя нет занятий и расписания** | Нет |

Основное действие для уволенного сотрудника — **«В архив»**. «Удалить» — второстепенное действие для исправления ошибок, его стоит прятать в меню «…».

Если сотрудник вернулся, его **восстанавливают**, а не создают заново. Тогда вся его история остаётся в одной карточке.

```
Активен ──в архив──► В архиве ──восстановить──► Активен
   │                    │
   └──удалить (только без занятий и расписания)──► удалён навсегда
```

## Общие правила API

- Все запросы отправляются с cookie сессии (`credentials: 'include'`).
- У сессии должна быть выбрана активная организация (`session.activeOrganizationId` в `GET /auth/me`). Все операции выполняются в ней.
- Даты (`startedOn`, `endedOn`) передаются и приходят строкой `YYYY-MM-DD`, без времени и часового пояса.
- Тексты ошибок (`message`) на английском и не предназначены для показа пользователю. Различайте ошибки по **эндпоинту и HTTP-статусу** (а для `POST /teachers` — по наличию `archivedTeacherId`) и показывайте свои тексты.

### Права

Роль пользователя в активной организации берётся из `GET /auth/me`: `organizations.find(o => o.id === session.activeOrganizationId).role`.

| Действие | Роли |
|---|---|
| Смотреть список и карточку | `owner`, `admin`, `manager`, `accountant` |
| Создавать, архивировать, восстанавливать, удалять | `owner`, `admin` |

Кнопки «Добавить», «В архив», «Восстановить», «Удалить» показывайте только `owner` и `admin`. Роль `teacher` раздел учителей не видит.

### Формат ошибок

```ts
// 400, 404, 409 и 403 «Insufficient permissions»
type ApiError = {
  statusCode: number;
  error: string;               // 'Bad Request' | 'Not Found' | 'Conflict' | 'Forbidden'
  message: string | string[];  // при ошибке валидации — массив строк
};

// 401: { message: 'Unauthorized', statusCode: 401 }
// 403 без выбранной организации: { message: 'Active organization is required' }
```

Ошибки, общие для всех эндпоинтов ниже:

| Статус | Когда | Что делать |
|---|---|---|
| 401 | Нет сессии или она истекла | Перенаправить на вход |
| 403 `Active organization is required` | Не выбрана организация | Перенаправить на страницу выбора организации |
| 403 `Insufficient permissions` | У роли нет прав на действие | Тост «Недостаточно прав». Обычно до этого не доходит, если кнопки скрыты по ролям |
| 400 `["Invalid UUID"]` | В URL не UUID | Ошибка фронта, на практике не возникает |

## Модель учителя

Все эндпоинты, которые возвращают учителя, отдают такой объект:

```ts
type Teacher = {
  id: string;               // UUID
  fullName: string;
  email: string | null;
  phone: string | null;
  telegram: string | null;  // username без «@»
  hourlyRate: string;       // десятичная строка: '1500.00'
  startedOn: string;        // 'YYYY-MM-DD'
  endedOn: string | null;   // дата увольнения; у активных null
  isActive: boolean;        // false = в архиве
  createdAt: string;        // ISO 8601
};
```

Учитель в архиве — это `isActive === false`, и у него всегда заполнено `endedOn`.

## Что сделать в интерфейсе

### 1. Список учителей: вкладки «Активные» и «Архив»

`GET /teachers?status=active|archived|all&search=&limit=20&offset=0`

- Вкладки «Активные» (`status=active`, по умолчанию) и «Архив» (`status=archived`). Вариант `all` нужен, если хочется единый список.
- В архивной вкладке у строки показывайте «Уволен {endedOn}».
- Действия в строке:
  - активный учитель: «В архив», в меню «…» — «Удалить»;
  - учитель в архиве: «Восстановить», в меню «…» — «Удалить».

Ответ `200`:

```ts
type TeacherList = { items: Teacher[]; total: number; limit: number; offset: number };
```

Ошибки: `400`, если `limit` вне 1–100, `offset < 0` или неизвестный `status`.

> Учителей в архиве **нельзя** предлагать в выпадающих списках при планировании занятий: для них запрашивайте `status=active`. В истории занятий и отчётах они при этом остаются видны.

### 2. Карточка учителя

`GET /teachers/:id` возвращает и активных, и архивных учителей. Архивного нужно открывать, например, по ссылке из истории занятий.

- Если `isActive === false`, покажите плашку «В архиве с {endedOn}» и кнопку «Восстановить» вместо «В архив».
- `404` — учителя нет (удалён или из другой организации): экран «Учитель не найден».

### 3. Перевод в архив

`POST /teachers/:id/archive`

Перед запросом покажите диалог подтверждения:

> **Перевести «{fullName}» в архив?**
> Дата увольнения: [сегодня ▾]
> Будущие запланированные занятия учителя будут отменены, расписание закрыто. Проведённые занятия и выплаты сохранятся. Учителя можно будет восстановить.
> [Отмена] [В архив]

- Дата увольнения необязательна. Без неё бэкенд берёт сегодняшнюю дату по часовому поясу школы.
- В date picker ограничьте выбор диапазоном от `startedOn` до сегодня: бэкенд проверяет то же самое.

Запрос:

```json
{ "endedOn": "2026-10-20" }
```

Тело можно не передавать вовсе.

Ответ `200`: обновлённый `Teacher` с `isActive: false` и заполненным `endedOn`. Уберите строку из вкладки «Активные» или перезапросите список.

| Статус | `message` | Что показать |
|---|---|---|
| 400 | `endedOn cannot be in the future` | «Дата увольнения не может быть в будущем» |
| 400 | `endedOn cannot be earlier than startedOn` | «Дата увольнения раньше даты начала работы» |
| 400 | `["endedOn: Invalid ISO date"]` | Неверный формат даты (ошибка фронта) |
| 404 | `Teacher not found` | «Учитель не найден», обновить список |
| 409 | `Teacher is already archived` | Учитель уже в архиве (его архивировали в другой вкладке): обновить данные |

Важно: бэкенд **отменяет** будущие занятия, а не передаёт их другому учителю. Количество отменяемых занятий заранее он пока не сообщает. Передачу занятий другому учителю добавим вместе с эндпоинтами занятий.

### 4. Восстановление из архива

`POST /teachers/:id/restore`, тело не нужно.

Подтверждение можно не спрашивать: действие безопасное. После успеха покажите подсказку «Учитель восстановлен. Расписание нужно составить заново»: отменённые при архивации занятия не возвращаются.

Ответ `200`: `Teacher` с `isActive: true` и `endedOn: null`.

| Статус | `message` | Что показать |
|---|---|---|
| 404 | `Teacher not found` | «Учитель не найден», обновить список |
| 409 | `Teacher is not archived` | Учитель уже активен: обновить данные |
| 409 | `Active teacher with this email already exists in the organization` | «Уже есть активный учитель с почтой {email}. Измените почту у одного из них» |

Ответы 409 различайте по `message`: это единственный эндпоинт, где у одного статуса две разные причины.

### 5. Удаление

`DELETE /teachers/:id`

Диалог подтверждения:

> **Удалить «{fullName}» безвозвратно?**
> Используйте удаление, только если карточку создали по ошибке. Если учитель уволился, переведите его в архив.
> [Отмена] [Удалить]

Ответ `204` без тела. Уберите строку из списка.

| Статус | `message` | Что показать |
|---|---|---|
| 404 | `Teacher not found` | Уже удалён: обновить список |
| 409 | `Teacher has lessons or schedule rules and cannot be deleted; archive the teacher instead` | «У учителя есть занятия или расписание, удалить нельзя». Для активного учителя добавьте кнопку «Перевести в архив», которая открывает диалог из п. 3 |

Заранее бэкенд не сообщает, можно ли удалить учителя. Поэтому кнопку «Удалить» показывайте всегда, а 409 обрабатывайте как обычный сценарий.

### 6. Добавление учителя с почтой из архива

`POST /teachers`

Если почта нового учителя совпадает с почтой учителя в архиве, бэкенд не создаёт дубль, а возвращает `409` с `archivedTeacherId`:

```json
{
  "statusCode": 409,
  "error": "Conflict",
  "message": "Archived teacher with this email exists; restore the teacher instead",
  "archivedTeacherId": "01a15411-0000-7000-8000-000000000002"
}
```

Покажите диалог:

> **Этот учитель уже работал у вас**
> Учитель с почтой {email} в архиве. Восстановите его, чтобы сохранить историю занятий.
> [Открыть карточку] [Восстановить]

«Восстановить» вызывает `POST /teachers/{archivedTeacherId}/restore` и открывает карточку. Данные из формы при этом не применяются: ставку и остальные поля учителя пока нельзя изменить через API, эндпоинт редактирования появится позже.

| Статус | Признак | Что показать |
|---|---|---|
| 201 | — | Учитель создан |
| 409 | есть `archivedTeacherId` | Диалог восстановления (выше) |
| 409 | нет `archivedTeacherId` | «Учитель с такой почтой уже есть» у поля почты |
| 400 | `message` — массив `"поле: ошибка"` | Подсветить поля формы |

Пример обработки:

```ts
const res = await fetch(`${API}/teachers`, {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(form),
});

if (res.status === 409) {
  const body = await res.json();

  if (body.archivedTeacherId) {
    return openRestoreDialog(body.archivedTeacherId);
  }

  return setFieldError('email', 'Учитель с такой почтой уже есть');
}
```

## Сводка эндпоинтов

| Метод и путь | Тело | Успех | Ошибки |
|---|---|---|---|
| `GET /teachers` | — | 200 `TeacherList` | 400 |
| `GET /teachers/:id` | — | 200 `Teacher` | 404 |
| `POST /teachers` | форма учителя | 201 `Teacher` | 400, 409 (с `archivedTeacherId` или без) |
| `POST /teachers/:id/archive` | `{ endedOn? }` | 200 `Teacher` | 400, 404, 409 |
| `POST /teachers/:id/restore` | — | 200 `Teacher` | 404, 409 |
| `DELETE /teachers/:id` | — | 204 | 404, 409 |

К каждому эндпоинту также относятся общие 401 и 403 (см. «Формат ошибок»).

## Чего пока нет на бэкенде

- **Передачи будущих занятий другому учителю** при архивации: сейчас они только отменяются.
- **Предпросмотра** перед архивацией и удалением («будет отменено N занятий», «удалить нельзя»).
- **Редактирования учителя** (`PATCH /teachers/:id`): после восстановления нельзя сменить ставку или дату начала работы.
- **Отзыва доступа** к организации при архивации: появится вместе с личным кабинетом учителя.
